# 真实抽取的小样本图谱实验

本轮由用户运行真实抽取模型，不用人工标注实体代替模型。代理只执行预检和脚本检查，没有发出真实模型请求。实验读取现有 v3 父子块，单独生成小图谱；旧知识库、两轮向量检索结果和上传流程保持原样。

后续的[打印机业务抽取规范 v1](PrinterBusinessExtraction-zh.md)增加了机构类型、关系端点约束及带引用的条件数组，使用独立入口与新目录。本页原实验和六次历史响应保留用于对照，不能用新规范直接恢复旧计划。

## 实验问题与样本

要检查两件事：模型能否从真实原文抽出正确实体/关系；同一批结果经过不同建图及查询规则后，是否混淆场景和型号。

| 样本 | 原文位置 | 内容 |
| --- | --- | --- |
| S01 | B 手册，网络连接报告 E-12 小节 | 网络问题的说明与处理 |
| S02 | B 手册，显示屏错误代码表 | E-12 原始表格行、表头及脚注 |
| S03 | B 手册，同一错误代码表 | W-11 原始表格行、表头及脚注 |
| S04 | C 手册，显示屏错误代码表 | W-11 原始表格行、表头及脚注 |
| S05 | B 手册，手册介绍 | “以下功能仅适用于 L5298”及连续功能清单 |
| S06 | B 手册，ADF 规格 | 明确的适用型号和规格说明 |

样本自动从真实父块、表格和范围声明中选择；找不到唯一来源时预检失败，不猜测替代。表格样本是保留原值的行投影，记录原表格 ID 和行索引，不冒充连续原文。样本记录文档、父块、对应子块、原始块字符区间、父块页码范围及脚注 JSON 来源。页码范围可能覆盖整张表格所在的多页，不声称是某一行的精确页码。

## 真实调用流程

```text
6 份真实原文 → 现有 EXTRACT 模型真实调用（每份一次）
                         ↓
               保存原始响应与抽取结果
                         ↓
           用同一批抽取结果建立两张小图谱
             ├─ name_only：实体按名称合并
             └─ scoped：故障码按场景区分，事实保留来源与型号
                         ↓
              8 个固定问题的一跳查询对照
```

只调用配置中的 EXTRACT 模型，角色未配置的字段按基础 LLM 配置继承。目前预检解析到 `Qwen3.5-Plus`。使用专门的设备领域抽取提示，要求返回实体、关系和逐条原文引文；不是项目默认提示词的原样复刻，也不通过当前线上入库流程。两张图共用真实响应，因此本实验主要检查真实抽取加身份/范围处理，不比较两个不同模型或两套提示。

图谱使用独立的 NetworkX MultiDiGraph，并保存节点/关系 JSON。事实边分别保留来源，不将不同手册的按钮说明摘要成一条通用操作。故障码身份包含已整理的功能域；设备/功能实体可按类型与名称共享，其他实体按类型、名称、场景和文档区分。这是小范围候选策略，不是已接入系统的最终实体合并算法，也不是现有 LightRAG 全流程的性能对照。

不调用 embedding、关键词模型、自动评分模型或回答生成模型。查询通过程序从问题中识别明确的型号、故障码和“网络连接报告/显示屏”等词，再查图谱相邻事实。识别不了的自然语言不在本轮能力范围内。G03 的 E-12 未明确场景；G06 的 W-11 未提供型号，检查程序是否保留待确认状态。不能把程序产生的待确认状态描述成模型已经学会追问。

G07/G08 检查真实抽出的 ADF/传真限制关系是否可查，以及返回证据是否保留 L5298。不会把手工标注结论或上一轮 CapabilityIndex 的判断结果插入图谱补足模型漏抽；需要人工核对是否足以支持纠正用户前提。

## 请求范围与预算

- 计划 6 次顺序抽取请求，每份成功响应只调用一次；没有自动补抽、修复或评审请求。
- 每次最大输出 4096 token，六份合计输出上限 24576 token；该数是上限，不是预估消耗。输入总量以预检打印的本地 cl100k 计数为准，实际服务商计数及费用以 usage/账单为准。
- 温度固定为 0，继承现有 EXTRACT 的超时与兼容选项，包括当前的关闭思考配置。
- HTTP 错误或超时不自动重试；成功响应保存后恢复运行会复用。没有保存响应的中断请求可能需要重新发出，不能保证服务商没有对中断请求计费。
- 结构错误、原文引文无法定位、关系端点不存在或输出截断时，保留原始响应，记录验证失败，不偷偷生成实体补齐。正常完成六份后如存在这些失败，脚本退出码为 2，可查看报告。
- 引文存在不代表关系含义正确，输出仍需人工审阅。结构合法但漏抽、错误解释、缺失条件，都可能出现在报告中。

## 运行命令

在本地 PowerShell 执行，不需要启动 LightRAG 或 Docling 服务。

先预检，检查源文件、模型配置、提示和请求范围，不请求模型：

```powershell
Set-Location D:\GitHubCode\LightRAG
.\examples\parent_blocks\run_printer_graph_smoke.ps1 -Resume
```

预检目录包含 `samples.json`、`prompts.json`、`queries.json`、`experiment.json`，可先检查实际将发给模型的原文和提示。问题及验收标准不进入模型请求；模型只接收对应原文及文档/章节/场景背景。

正式运行，由用户执行：

```powershell
.\examples\parent_blocks\run_printer_graph_smoke.ps1 -RunExperiment -Resume
```

默认目录 `outputs/printer_graph_smoke/manual_run_v2`。此前的 `dev_preflight_v1` 和 `manual_run_v1` 仅为开发预检记录，未调用模型；当前版本已补齐 B 手册正文中的编号脚注，不从旧预检恢复。如果需要改模型、提示、脚本、输入来源或输出上限，必须另选目录，例如：

```powershell
.\examples\parent_blocks\run_printer_graph_smoke.ps1 `
  -OutputDirectory outputs/printer_graph_smoke/manual_run_v3 `
  -MaxOutputTokens 6144
```

同样参数下添加 `-RunExperiment -Resume` 才真正调用。不要在同一目录同时运行；恢复要求计划不变。结构失败的已保存响应会保留复用，不因重跑命令而自动重新付费抽取。

## 看什么结果

| 文件 | 用途 |
| --- | --- |
| `raw/S*.json` | 服务端原始模型响应、usage 和耗时 |
| `extractions.json` | 结构及引文检查通过的模型实体关系 |
| `validation.json` | 结构/引文失败及待人工审阅状态 |
| `graph_name_only.json` | 按名称合并的实验图谱 |
| `graph_scoped.json` | 带场景身份、来源事实和范围的实验图谱 |
| `retrieval_results.json` | 8 问题 × 2 策略的事实、来源及待确认状态 |
| `report.md` | 样本抽取情况、查询对照与验收提示 |
| `summary.json` | 配置身份、请求数与累计 usage |

主要验收：E-12 两种含义及操作不串场景；W-11 的按钮及警告不串手册；ADF/传真限制不丢失；没有明确场景/型号时不默选一个操作。没有正确抽取相关关系时应记录失败，不能凭图节点数量或 JSON 校验通过宣布优化成功。

完成后提供 `report.md`、`extractions.json`、`retrieval_results.json`；如有失败，再提供 `validation.json`。本轮没有自动准确率或回答质量分数。

## 首次真实运行的校验失败与无 API 复核

用户已完成 6 次真实请求，服务端全部返回正常。原始严格校验为 2/6，通过的只是完整样本；失败 4 份不代表这些样本的所有实体关系都不可用。具体发现：

- S01：一条关系把两段不连续原文拼接为一条引文。
- S03：部分引文额外包了一层引号，另有两条关系使用省略号形式的引文。
- S04：一条关系使用省略号形式的引文。
- S06：两条关系使用约定列表之外的 `DEPENDS_ON`。

退出码 2 用于提示这些失败。原始仅含两份样本的图谱不足以比较两种 E-12 和跨手册 W-11，不应解释成消歧效果已经失败。

新增 `replay_printer_graph_smoke` 对已保存的真实响应逐条检查：有效记录保留；无效记录及依赖被拒实体的关系隔离；额外配对外引号仅在去掉一层后仍能连续匹配原文时处理，并记录前后文本。省略号、拼接引文及未知关系不自动修复或映射。原始响应和原始整份失败状态均保留，复核结果另存。

运行以下命令，不读取 API 配置、不请求模型：

```powershell
.\.venv\Scripts\python.exe -m lightrag.evaluation.replay_printer_graph_smoke `
  --source-directory outputs/printer_graph_smoke/manual_run_v2 `
  --output outputs/printer_graph_smoke/manual_run_v2_review_v1
```

只看复核计数且不生成文件，可额外加 `--preflight`。输出目录必须是新目录，不覆盖原实验；本轮复核没有恢复调用或重新付费抽取。

当前真实响应的逐条复核预检：可保留 43 个实体记录、39 条关系，隔离 6 条关系，处理 13 处额外外引号。该计数不是语义正确率。原始整份严格通过仍为 2/6，复核状态为 `reviewed_with_rejections`。

新目录中的 `record_review.json` 保存每条拒绝记录、原因和格式处理日志，`extractions.json`、两张 `graph_*.json`、`retrieval_results.json` 和 `report.md` 使用保留的真实记录。尚未运行复核生成新图谱时，不提前宣称 E-12 或 W-11 查询已通过。
