# 设备手册整理与父子块的一键接入设计

状态：共享整理 API、离线子块与父块回取检查已实现，见 [离线父子块说明](ParentChildOfflinePreparation-zh.md)。尚未接入上传、在线索引或查询；下文产品操作、持久化和调度接入是后续设计。

## 用户操作

上传时选择“设备手册 · 父子块”处理方案，点击开始；可将方案保存为工作区默认值，之后上传直接应用。系统完成解析、恢复结构、组织父块、切分子块和索引，展示每一步的状态与结果。用户不需要执行整理脚本或逐块标注。

这是拟新增的处理方案，不是当前界面已有选项。首次解析新 PDF 或解析配置变化时仍需要 Docling 服务；有效解析缓存可复用。父块整理和普通递归子块切分在本地执行，不需要 LLM。索引与图谱抽取仍沿用配置的 embedding / LLM 服务及相应成本。

## 固定的型号策略

1. 从原始上传文件名提取型号，作为文档及普通父块的默认适用范围。内部临时路径或图片文件名不得作为型号来源。
2. 父块标题、所属章节路径或正文开头明确限定整个单元时，与文件名范围取交集；明确排除时做差集，不能扩大文件名范围。
3. 标题只写“ADF”“传真”等功能词，不能仅凭以前的功能映射规则缩小范围。
4. 某按钮、表格项目或步骤的脚注限制是局部条件，不能使整个父块改成单一型号。条件需保留；适用范围尚未精确定位的片段应提示复核。
5. 文件名没有可识别型号且原文也无明确范围时保留未知；有冲突时报告冲突，不能当作通用。

该规则是用户指定的业务策略，不表示文件名是厂商适用性声明。输出记录 `policy=filename_default_explicit_parent_limits` 和对应证据。

## 后端接入路径

```text
上传并保存原始文件名、处理方案快照
  → 现有解析调度：Docling / 有效解析缓存
  → 结构整理：书签、Docling 块、父块、适用范围、审阅事项
  → 父块内切分子块：普通文本复用 R，表格与图片保持结构
  → 保存父块及父子映射，子块进入现有索引流程
  → 查询命中子块后按条件筛选，回取父块及必要前置说明
```

当前 `lightrag/evaluation/prepare_parent_blocks.py` 是保留的离线入口，已调用 `lightrag/document_structure/parents.py` 的共享实现。输入读取、结构对齐、父块构建可通过 `organize` 在内存中完成；`children.py` 提供子块构建，`retrieval.py` 提供按已选子块回取父块的检查。后续上传适配器复用这些 API，而不再维护另一套整理规则。

可以先通过现有自定义切块 C 的 context-aware 扩展入口接入。`ChunkingContext` 已提供 `doc_id`、`file_path`、`sidecar_location`、`parse_engine` 等，实际构造位置位于 `lightrag/pipeline.py`。原始文件名、处理方案与版本等缺失信息需要作为文档元数据贯穿流水线，不能依赖进程全局变量。

后续由 API 的类型化处理配置和前端统一提供“设备手册 · 父子块”方案。方案同时选择解析器、结构规则、型号策略和子块参数；单独改一个 F/R/P/C 选择器不能完成整套能力。

`build_chunks_dict_from_chunking_result` 会保留大部分额外字段，可承载 `parent_id`、来源与范围，但这只说明字段可保存。最终 token 限制再次拆分时必须继续保留这些字段，且各种向量后端的元数据过滤仍需单独接通。

## 存储、回取与重试

- 父块保存完整上下文、来源范围、适用条件、结构版本和 `context_parent_ids`；子块保存 `parent_id`、顺序、同一版本及精确来源。父块不默认再做一轮重复图谱抽取。
- 父块可用独立 KV namespace 保存，子块沿用现有 text_chunks 和向量索引。必须补上初始化、刷新、文档归属、删除和重试逻辑，不能只临时写一份 JSON 就宣称已完成系统集成。
- 查询在同一工作区和文档版本内通过子块回取父块，合并重复命中的父块，保留来源和适用条件；必要的前置父块也要检查范围并纳入预算。图谱路径还需验证型号和功能域，不能假定父子块自动消除 E-12 歧义。
- 解析缓存身份与整理缓存身份分开：整理指纹至少包含 PDF 内容哈希、文件名提取的型号集合、解析配置、结构规则和型号策略版本、子块参数。改文件名中的型号或改规则后，不能错误复用旧范围。
- 重传相同文件、相同方案且已成功时复用结果；规则变更需要显式重新处理。现有上传去重可能提前跳过重复文件，需与重新处理入口一起验证。
- 失败记录具体阶段，并通过现有流水线重试机制恢复；不静默退回旧切分并显示成功。遵守现有并发与删除恢复契约，不绕过调度器启动另一套后台任务。

## 通用规则与手册特例

书签读取、页码标题坐标对齐、父块内切分、文件名默认范围和显式限制识别是共享能力。

这三份手册的 13.99 / 13.20 点标题框高度规则属于已复核版式特例，不能直接套用所有新文档。相同手册可通过内容指纹匹配版本化规则；新文档使用可验证结构，证据不足时输出结构降级或待复核状态。没有书签的文档也需要明示其所用的替代结构来源，不能假装恢复了书签。

## 分阶段交付与验收

1. 共享整理模块和离线父子块：同一输入与同一方案产生稳定结果，来源覆盖完整，局部条件不扩大作用范围。
2. 上传流程接入及父块持久化：一次操作产生父子关联，重复上传可复用，失败后可恢复，删除不留无归属的数据。先在独立实验 workspace 验证。
3. 查询回取和界面方案：子块命中后能得到正确父块、条件、页码和必要前置说明；验证型号差异、操作按钮、耗材与不同领域的同名故障码。

正式实现时按涉及模块补对应测试。涉及 pipeline、存储及删除时先阅读相应设计契约；前端变更运行完整前端检查。旧知识库和既有基线继续保留。
