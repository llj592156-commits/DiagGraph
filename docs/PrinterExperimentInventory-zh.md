### 分块对照结果

GLM-Embedding-3，Top-K=5，最终证据预算 8000 tokens；本实验未生成答案。

| 组别 | 平均参考引文覆盖率 | 参考引文全部覆盖 | 零覆盖 |
|---|---:|---:|---:|
| 旧分块 | 59.7% | 15/30 | 8/30 |
| 旧分块 + 实验性过滤 | 82.8% | 22/30 | 2/30 |
| 新子块检索 + 父块展开 | 86.3% | 24/30 | 2/30 |
| 新方案 + 实验性过滤 | 92.2% | 26/30 | 1/30 |

主要开发集观察：未加过滤的新旧方案相差 **26.7 个百分点**。新方案直接命中的子块覆盖率为 78.0%，展开后的最终证据为 86.3%。

这里的覆盖是“来源文档匹配，且规范化参考引文出现在证据中”，按题平均；它不是语义 Recall@K 或回答准确率。两组同时改变了解析、切块、元数据和展开，不能把全部收益归因于单一因素。92.2% 组还增加型号/能力约束；这些属于离线实验，不表示生产流程已接入型号硬过滤。v2 的 1 次请求、3 个新增嵌入输入仅是缓存复用后的增量，不能写成整个实验的总成本。

### 系统检索结果

| 模式 | 旧轮参考引文覆盖率 | 重排轮覆盖率 | 重排轮全部覆盖 |
|---|---:|---:|---:|
| naive | 74.7% | 85.2% | 23/30 |
| hybrid | 61.0% | 76.3% | 20/30 |
| mix | 74.3% | 89.7% | 25/30 |

重排轮 mix 零固定引文覆盖为 1/30，所有模式最终均有原文。候选、预算和数据清理同时发生变化，尚无同代码、同索引关闭重排的对照，不能将差值都归因于重排。缓存和运行负载不同，旧轮与本轮耗时也不用于证明加速。

固定文字匹配可能遗漏等价表述。Q06 的型号耗材混淆，Q19/Q20 的清洗前提及等待条件，Q25/Q26 的功能适用范围，Q30 的多型号证据覆盖，仍需要独立评估和实际答案复核。

## 3. 本次来源与结构完整性核验

新增工具：`python -m lightrag.evaluation.audit_parent_child_integrity`。直接读取文件，不实例化存储、不刷新缓存、不调用检索服务。

| 检查层 | 检查内容 | 实际结果 |
|---|---|---|
| 原始解析块 → 父块 | 原文覆盖、顺序、连续来源偏移、无丢失/重复，来源位置没有凭空增加或丢失 | 3/3 份通过 |
| 父块 → 子块 | 正文覆盖、原文子串或合法表格行投影、顺序、token 数、适用条件继承、表格及脚注保留 | 3/3 份通过；覆盖 1981 个子块 |
| 来源页码 | 父/子块页码与解析位置一致，位于准备报告记载的文档页数范围内 | 父块 710/710，子块 1981/1981 |
| 前提与附件来源 | 必要上下文来自同文档严格祖先；表格补充说明与冻结 sidecar 相符 | 3/3 份通过 |
| 入库一致性 | 父块、子块内容和元数据、归属文档、来源文件、父子关联与冻结产物一致 | 父块 710/710，子块 1981/1981 |
| 最终证据 | 从保存的支持子块、父块及前提重新拼出正文，核对来源映射、页码，防止静默截断 | 90/90 响应，398/398 组证据通过 |
| 输入稳定性 | 运行前后 SHA-256 相同；历史产物与记录哈希相符 | 28/28 文件未变化 |

语料含 11 个表格投影子块、6 次必需脚注引用、3 次表格补充说明引用。测试按实际出现次数统计，不能把同一脚注多次出现当成多个独立脚注。

**通过表示内容和来源链条一致，不表示人工确认了每页识别结果，也不表示每次检索都找到了正确答案。** 坐标来自解析片段，当前页码展示通常对应父章节页码范围，不能据此宣称每句话都有精确定位。仍有 24 个父块带 `inline_condition_requires_review` 标记；结构核验通过不消除语义适用条件的复核需求。

本地 v1 核验初次运行使用了错误的检查假设：将存储行内的局部 chunk_id 与包含文档前缀的命名空间 key 直接比较。修正工具后 v2 通过，v3 为最终工具版本复跑；三轮均未修改语料，不应把 v1 的失败解释为数据修复。

复跑命令（PowerShell，在已配置项目依赖的 Python 环境执行；输出目录必须是新的）：

```powershell
python -m lightrag.evaluation.audit_parent_child_integrity `
  --bundle outputs/printer_parent_child/20261017_v3/A `
  --bundle outputs/printer_parent_child/20261017_v3/B `
  --bundle outputs/printer_parent_child/20261017_v3/C `
  --tokenizer tmp/parent_blocks_tools/cl100k_base.tiktoken `
  --full-docs rag_storage/learning_paratera/kv_store_full_docs.json `
  --text-chunks rag_storage/learning_paratera/kv_store_text_chunks.json `
  --retrieval-results outputs/printer_system_retrieval/glm_rerank_v1/results.jsonl `
  --output outputs/parent_child_integrity/new_run
```

依赖本地的历史 bundle、原始 PDF、sidecar 和固定词表。缺少文件时应恢复对应快照，不要用当前知识库替代历史 407 块后重跑旧基线。输入在运行中变化会导致核验失败，应在稳定快照上复跑。退出码 0 表示所有检查通过，1 表示报告中存在失败。

## 4. 统一独立测试集的用途与下一步

**是的，主要为后续 Adaptive-RAG、Self-RAG 以及完整流程的公平比较准备，同时复用来评估分块和引用质量。** 本次只补齐确定性的结构核验，并未宣称已经建好独立测试集。

当前 36 题多次参与调试，保留为开发回归集，文件 SHA-256 为 `9d1eef0fbd15bc8b8a23c88f00efb3801070e1816b21f35c82926e55f174bc8b`。15 条路由标注样例也属于设计样例，不是最终测评成绩。

下一步建议：

1. 另建并人工复核一批独立问题。覆盖 direct、clarify、retrieve、diagnose、escalate，并包含型号混淆、关键前提、资料不足和多轮补充。多轮对话按整个会话划分，语义近似题不跨开发/测试集。
2. 每题标注可接受策略、预期行为、来源文档/章节/页码/必要原文、禁止遗漏的前提、是否应拒答或追问。允许多个合理策略，避免强制唯一标签。冻结题集后不再据测试结果反复改提示词。
3. 分块评估固定模型、检索和预算，比较旧块、新子块、新子块+父块，报告证据覆盖、引用可追溯率及操作前提完整率。准备旧索引/产物快照后才能执行。
4. Adaptive-RAG 对比预先固定的处理策略与自动路由；评估路由 macro-F1/混淆矩阵及端到端成功率、误追问/危险漏升级率、tokens、耗时 P50/P95。检索模式变化与路由变化分开记录。
5. Self-RAG 在相同输入和检索证据上比较：仅生成、+证据评价、+答案核验、两者均开启。评价正确率、事实支持率、前提完整率、正确拒答/误拒答及额外成本；涉及补检索或修订的完整流程再单独比较。
6. 保持模型版本、非思考配置、语料、预算及并发一致，记录缓存、重试和失败；区分逻辑模型调用与供应商 HTTP 请求，缺失用 null 而不是 0。先做质量对比，再做独立负载测试。

简历目前可以写开发集上的“参考引文覆盖率从 59.7% 提升到 86.3%，提高 26.7 个百分点”，并注明组合改进；可以写“完成三份手册、710 父块/1981 子块及 398 组历史证据的来源完整性核验”。Adaptive-RAG 和 Self-RAG 的提升数字，需要等独立对照实验完成后再填写。
