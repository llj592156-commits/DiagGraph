# 父子分块的现有系统接入

父子分块 H 与 F、R、V、P、C 并列，使用当前 LightRAG 实例、working_dir、workspace 和现有存储。切分与抽取方案独立，默认 generic 保持原抽取；可另选 printer_v2 使用新版业务抽取及身份转换，见 [业务图谱系统接入](PrinterGraphSystemIntegration-zh.md)。型号/场景查询硬过滤尚未接入。

## 使用方式

重启更新后的后端，并更新 WebUI 构建。在“上传文档”对话框的“切分方式”中选择“父子分块 · 设备手册（H）”，然后上传 PDF。默认子块大小为 500 tokens，重叠为 60 tokens。选择“沿用已有配置”时保持原行为。

也可以沿用已有文件名提示通道：

```text
L3266_L3267_L3268_L3269_L5298_UG.[docling-H].pdf
L3266_L3267_L3268_L3269_L5298_UG.[docling-H(chunk_ts=500,chunk_ol=60)].pdf
```

网页选择 H 会通过同一通道指定 Docling，保留原有 Docling 参数和跳过建图的 `!` 标志。逻辑文件名仍为原 PDF 名称，型号范围以该名称为默认来源。已有其他切分策略也可在下拉框中选择。

首次解析仍需要 Docling 服务。H 需要原始 PDF、结构化解析 sidecars 和仓库中的版本化整理规则；条件不满足时明确失败，不退回固定切分。纯文本插入不能选择 H。H 已直接处理结构化表格，本版拒绝与独立 i/t/e 分析叠加，以免附加块绕过父子来源映射。

## 整理与保存

复用已有整理程序读取 PDF 书签、对齐 Docling 块、组织父块，再在父块内部切分子块。表格表头、相关脚注、必要前置父块及页码来源继续保留。父块默认采用文件名型号，只有明确限制整个父块的描述才缩小父块范围；局部脚注不改变整个父块范围。

- 父块包、源文件指纹和规则指纹保存在现有 `full_docs[doc_id].parent_child`。
- 子块进入现有 `text_chunks` 和 `chunks_vdb`，`parent_child` 字段保存父块 ID、原始结构子块 ID、来源片段、标题、页码和范围。
- 图谱抽取接收子块，按文档排队时保存的抽取配置选择 generic 或 printer_v2。单独选择 H 不会自动切换业务方案。
- 最终向量硬拆分保留父子元数据；父块记录实际发布后的 `indexed_chunk_ids`。结构跨度仍描述原始结构子块，不能声称已精确到硬拆分片段中的每个字符。

先保存所属文档的父块包，再发布子块。子块阶段失败可能留下该文档上的未使用父块包；现有人工重试覆盖它，按文档删除时随 full_docs 行删除。这个中间状态有明确归属，不创建额外存储或独立知识库，也不改变现有并发调度和图谱恢复锚点。

## 父块回查

naive 以及原有 local/global/hybrid/mix 选出来源子块后，通过 `full_doc_id`、`parent_id` 回查当前 full_docs 中的父块。相同父块只展开一次，附加必要前置父块和表格脚注，再按原有重排、上下文预算生成检索上下文。普通切分产生的块保持原行为。

此处只沿来源映射扩展证据，不按问题推断型号能力，不过滤图谱实体或关系，不解决 E-12 等同名故障码歧义。保存的范围和条件可供后续图谱优化使用。父块、所属文档或映射缺失时明确报错，避免把断裂的来源当作成功回查。H 回答缓存包含实际证据上下文身份，避免复用证据不同的旧答案。

## 已有数据和验证边界

已有三份文档及旧知识库不自动转换，也未被本轮重建。相同源文件仍受原有上传去重约束；升级后出现 H 选项，不表示旧文档已经改为 H。不要直接覆盖、删除现有知识库来试用。

开发验证使用模拟 LLM/embedding，覆盖原生流水线、现有存储、普通图谱抽取、五种检索模式的父块回查、硬拆分映射及按文档删除。三份真实 PDF 与已有 Docling 产物在本地复核得到 710 个父块、1981 个结构子块；未进行全量模型抽取或向量重建。

新版业务提示与六样本实验保留为模型效果审核材料，见 [业务抽取说明](PrinterBusinessExtraction-zh.md)。可选的建图代码接入不等于已完成真实小样本验收或全量建图。
