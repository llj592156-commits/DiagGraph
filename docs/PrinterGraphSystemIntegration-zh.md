# 打印机业务抽取与消歧接入

新版方案已作为可选配置接入现有 LightRAG 入库流程。默认仍为 `generic`，使用当前配置的原有提示和抽取方式。切分策略 F、R、V、P、C、H 与抽取方案独立；不创建独立知识库，不自动重处理已有文档。

## 选择方案

后端启动前，可在 PowerShell 设置：

```powershell
$env:EXTRACTION_PROFILE = 'printer_v2'
# 在同一窗口按平时方式启动 LightRAG 后端
```

也可在 `.env` 中填写 `EXTRACTION_PROFILE=printer_v2`，然后重启后端。本轮没有修改实际 `.env`，也没有启用真实模型调用。恢复新文档的原有抽取可设置为 `generic`。

核心 API 同样支持：

```python
rag = LightRAG(
    # 保留原有 working_dir、workspace、模型和存储配置
    addon_params={"extraction_profile": "printer_v2"},
)
await rag.initialize_storages()
```

此参数应与其他已有 addon_params 合并，不应据此替换整个现有初始化配置。当前通过后端配置选择，网页新增的下拉框仍只选择切分方式，没有新增业务抽取下拉框。

## 入库路径

1. 排队时在现有 `full_docs[doc_id].extraction_config` 保存方案、业务合同版本、提示指纹和身份规则版本。
2. 任一切分方式产生最终子块后，将已保存的新版配置附在子块上；向量硬拆分也使用最终子块 ID。排队后修改默认配置，不改变该文档方案。
3. 新版块通过现有 EXTRACT role 和抽取缓存调用 `printer-business-extraction-v2`。使用增强 JSON 格式，不依赖通用抽取的 JSON 开关，不额外执行通用补抽。
4. 对实体和关系逐条检查格式、完整代码、引用、关系端点类型及型号限制。不合格记录隔离，保留原因；输出整体不可解析、必要字段缺失或截断时，将该子块标为跳过并保留原文、原始回答和错误，其他块继续。不把网络、来源或存储故障当成格式错误跳过。
5. 在原有合并之前生成实体身份，并同时转换关系两端，然后沿用 `merge_nodes_and_edges`、恢复锚点、图存储及实体/关系向量索引。

提示仍使用六样本阶段定义的 12 实体、16 关系上限。它是当前业务合同的一部分，不能将小样本结果当作大块文本的完整抽取证明。原文引用存在只证明文本可找到，不证明模型语义理解正确，记录始终带有 `semantic_review_required`。

原生接纳阶段按原始记录顺序隔离超过 12/16 条预算的记录，以及引用已隔离实体的关系。端点与引用校验保持严格。JSON 结构错误或截断使该子块不贡献实体关系，保留来源和跳过状态，允许剩余子块继续入库；不猜测或补造缺失字段。缓存重建沿用同样的跳过规则，避免坏回答在重建时重新引起整文档失败。六样本独立实验继续使用原有严格检查。隔离记录和原始响应保留，流程完成不等于完整性验收通过。

## 来源和身份

`text_chunks[chunk_id].business_extraction` 保存本次校验结果、隔离原因、实体身份目录、事实原文引用、限定条件和适用型号。原始响应仍沿用原有抽取缓存；保留 reference-before-cache-row 顺序。写证据前重新读取 chunk，避免覆盖本次缓存新附加的 `llm_cache_list`。

`business_extraction_attempt` 另存本次原始响应、时间与截断标志，格式错误和正常缓存拒收的截断响应也可检查，不把它们当成有效图谱记录。显式 DeviceModel 端点约束对应事实的型号，例如 `L5298 SUPPORTS 传真` 不会扩展到同一文件名中的其他型号。

身份形式类似 `E-12 ⟦printer:24位摘要⟧`。摘要输入包含身份版本、文档 ID、场景、实体类型、名称和型号集合：

- 已知场景且型号明确的故障码，可以在同一文档、同一场景、同一型号集合内合并。
- 其他对象按真实父块隔离；普通切分没有父块时按真实来源子块隔离。
- 未知场景或未知型号的故障码也按来源单元隔离，不把“未知”当作共同的通用身份。
- 不同文档、类型、场景或型号集合不会因为名称相同而直接合并。

原生图后端的有向/无向性质不改变。关系的语义方向及限定条件保存在描述与事实记录中，多种事实可能映射到原生同一条边，事实记录仍分别保留。

文件名型号仍是默认范围；H 使用已整理的父块范围。模型输出的局部限制仅影响对应关系及端点身份，不修改整个父块范围。程序对带可核对原文的“仅对于/仅适用于”等独占限制和“除外/不适用”等排除限制作保守识别；表达不明确、范围冲突或范围交集为空时隔离该关系。场景识别只使用已有 H 场景或明确标题，无法确定时保持未知，不调用模型猜测。

非父子块没有 `parent_id` 时保留空值，继续通过真实 `chunk_id` 和 `full_doc_id` 回查正文及已有来源信息；不伪造父块。H 的父块回查继续使用既有父子来源映射。

## 缓存、失败和删除

缓存重建使用同一校验与身份转换，不把增强 JSON 当通用 JSON 重解释。合同指纹变化会拒绝隐式重解释，需要显式决定重处理。已有未保存方案的文档保持原有抽取，重试不会自动升级为新版。

证据写入可能先于后续图提交成功。若后续阶段失败，chunk 上保留待完成的证据和归属信息；现有人工重试覆盖并重新入库，按文档删除沿用恢复锚点清理。没有增加跨存储事务，也没有吞掉存储失败。受管理的业务实体禁止通过通用手工重命名或合并绕过来源身份；应修正来源后显式重处理。

## 本轮边界与下一步

代码接入已完成，软件检查使用模拟 LLM/embedding，并覆盖六种切分方式、排队配置快照、缓存重建、身份隔离、局部型号限制和现有存储的入库/删除路径。没有调用真实模型，没有重建三份手册，也没有修改已有知识库。

查询时按型号、场景、能力作硬过滤与追问尚未接入。当前原有检索可以召回这些新身份，但不能宣称已经具备完整的业务范围过滤。下一步由用户运行小样本真实入库，先检查抽取、身份、关系和来源，再推进检索优化与全量建图。

本轮相关离线回归共 413 项通过：抽取目录、addon_params，以及业务入库、父子入库、自定义切分、排队来源和状态元数据相关文件。沿用已知环境排除：缺少 Ollama 包的 `test_keyword_extraction_drivers.py`，以及 Windows 错误文案差异的 `test_prompt_file_rejects_absolute_paths`。新增代码 Ruff 与修改文件的未定义名称检查通过；没有运行全仓测试或重新扩大前端测试范围。
